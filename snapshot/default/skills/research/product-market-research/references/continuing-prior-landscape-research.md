# Continuing Prior Landscape Research

Use this when the user says the recommendation should be based on research already performed.

## Retrieval-first procedure

1. Search conversation history using both the user's wording and likely project/product names.
2. Open the most relevant session around its matched conclusion, not only the search snippet.
3. If that session points to a report, matrix, workbook, or source ledger, inspect that artifact before doing new research.
4. Extract the original scope constraints (for example: open-source only, self-hosted only, local-network operation, target operating systems, sender/receiver direction).
5. Tailor the existing eligible shortlist to the new deployment topology.
6. Refresh only claims that are time-sensitive or decisive, such as maintenance status, licensing, platform support, security defaults, and multi-client limits.
7. Cite the prior session when useful and distinguish inherited findings from newly verified facts.

## Eligibility gate

Before ranking, classify every candidate as:

- eligible under the original research scope;
- adjacent fallback;
- excluded.

Do not silently replace an open-source shortlist with commercial products merely because they are easier to recommend. Commercial alternatives may be mentioned only as a clearly separated fallback when the user asks for them or when no eligible option meets a hard requirement.

## Topology questions to resolve from context

- One source to one receiver, or one source to several receivers?
- One receiver switching among sources, or simultaneous mosaic?
- View-only or remote input/control?
- Same LAN only, Wi-Fi Direct, or remote access?
- Static office UI or latency-sensitive video/animation?

If these distinctions change the winner, present scenario-based recommendations rather than guessing one topology.
